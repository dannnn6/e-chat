# E-chat и личные чаты VKH — начать здесь

25 сентября 2026. Это два **пилотных пакета исходников**, а не подтверждённо готовые production-продукты. E-chat поставляется как сервер + PWA; VKH — как изменённый исходный Android/Windows-проект + добавочные PHP/SQL. APK/MSI не собраны. До рабочего внедрения обязательны сборка, staging и приёмка.

## Архивы

`E-chat_0.1.0_pilot.zip` распаковывается в `E-chat/`. Никаких учётных записей/таблиц VKH в нём нет. Отдельная PostgreSQL, отдельные ключи, отдельный HTTPS-поддомен. Для локального теста предусмотрена SQLite.

`VKH_private_chats_source.zip` распаковывается в `VKH-private-chats/`. Внутри `vkh/` — полный нативный исходный проект. В `backend/` — три новых API-файла, миграция и необязательная CLI-проверка. Существующие серверные config/lib/общий чат не заменяются.

`VKH_private_chats_patch.zip` — альтернативный небольшой пакет для применения к вашему существующему исходному проекту. Он НЕ является полным Android Studio-проектом: подпапка `vkh/` здесь содержит только 24 добавленных/изменённых файла. Используйте guarded-скрипт, не открывайте её вместо полноценного проекта.

Не устанавливайте полный пакет и патч последовательно как два независимых обновления: это два способа получить один и тот же исходный VKH.

## E-chat: локальный тест на Windows

Распакуйте архив и откройте PowerShell в `E-chat/`. Требуется Python 3.13 и доступ к репозиторию зависимостей.

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe scripts\dev.py
```

Откройте `http://127.0.0.1:18080`. Приглашение локального теста — `browser-test-invite`. Используйте два отдельных профиля браузера для двух аккаунтов. Сохраните каждый ключ восстановления; собеседнику сообщайте только публичный ID. Локальная история лежит в `data/dev`; приватное окно не подходит для постоянного хранения.

## E-chat: первый сервер

На сервере нужны Linux, Docker Engine + Compose plugin, Python 3 и собственный DNS-поддомен. Распакуйте проект вне публичного document root.

```sh
cd /opt/E-chat
python3 scripts/init.py echat.example.com
bash scripts/up.sh
curl --fail http://127.0.0.1:3080/health/ready
```

`echat.example.com` замените реальным именем. Генератор создаёт `.env` один раз; не удаляйте/не пересоздавайте его ради перезапуска. Сохраните защищённую копию. Настройте отдельный HTTPS virtual host текущего reverse proxy. Если NPM/OpenResty находится в Docker, `127.0.0.1` внутри него не указывает на хост — в `docs/DEPLOY.md` дан вариант общей proxy-сети с upstream `echat-api:8080`.

Не занимайте повторно 80/443 дополнительным Caddy, если их уже обслуживает ваша панель. Второй API-узел требует общей БД и общего файлового хранилища; он не создаёт независимую федерацию или отказоустойчивую БД. Пошаговые варианты backup/restore/второго узла — `E-chat/docs/DEPLOY.md`.

## VKH: безопасное добавление

1. Сохраните исходный проект, существующие server config/lib, БД, файлы и прежний keystore. Создайте staging без управления реальным оборудованием.
2. В ту БД, которую возвращает действующий `getDB()`, примените только `backend/migrations/20260925_01_direct_chats.sql`. Исходный полный SQL-дамп не импортируйте в рабочую БД.
3. В текущий `app/api/` добавьте `dm.php`, `dm_core.php`, `dm_media.php`. Старые endpoint не заменяйте.
4. Создайте закрытый media-каталог вне document root с правами процесса PHP. В защищённой существующей конфигурации задайте `VKH_DM_STORAGE_DIR` с фактическим путём, внутри контейнера — внутренним путём mount.
5. Откройте `VKH-private-chats/vkh` как отдельный полный проект либо примените альтернативный патч к исходной версии.

Проверка патча из корня его пакета:

```powershell
py apply_patch.py --project "C:\Users\YOUR_USER\AndroidStudioProjects\vkh"
```

После успешной проверки:

```powershell
py apply_patch.py --project "C:\Users\YOUR_USER\AndroidStudioProjects\vkh" --apply
```

При несовпадении хэшей скрипт не пишет файлы. Это означает, что исходная версия отличается; объедините изменения, не обходите защиту. Резервные копии заменяемых исходников сохраняются внутри `.vkh-private-backups/` вашего проекта. SQL и PHP этот скрипт не разворачивает.

Сборка из полноценной папки `vkh`:

```powershell
.\gradlew.bat :app:assembleDebug
.\gradlew.bat :desktopApp:run
.\gradlew.bat :desktopApp:packageReleaseMsi
```

Для обновления установленного Android release нужен **прежний `vkh-release.jks`**. Он исключён из поставки. Не удаляйте рабочее приложение ради debug APK. В исходниках версии 141 / 1.14.12 и Desktop 4 / 0.1.3; перед публикацией сверяйте с уже опубликованными кодами. Toolchain сохранён от приложенного архива; его доступность и реальные сборки ещё нужно проверить.

Полная установка, DPoP/FCM, ограничения WorkManager и откат: `VKH-private-chats/docs/DEPLOY.md`. Необязательный изолированный MySQL/PHP тест: `bash tests/run.sh`; тестовая dummy-auth конфигурация никогда не копируется в production.

## Что проверено и что нет

Реально прошли 17 E-chat тестов на SQLite/TestClient и Node WebCrypto, HTTP-запуск локального dev-сервера, выдача 7 ресурсов веб-клиента. Браузерный сценарий остановился на запрете локального адреса Chromium до регистрации; успешной UI-проверки нет.

VKH: 209 исходных файлов совпадают побайтно, 8 изменены, 16 добавлены. PSI-разбор 23 Kotlin/Kotlin DSL-файлов — без синтаксических ошибок; PHP lint и guarded patch прошли свои проверки. Полная Gradle-сборка заблокирована недоступностью `services.gradle.org`, поэтому ошибки типов/устройственного поведения ещё не исключены.

PostgreSQL, Docker, реальный MySQL/DPoP/FCM, Android/Windows, настоящий EDGE, NFS-кластер, нагрузка и восстановление на ваших серверах не проверены. Все логи находятся в `verification/`; планы приёмки — в `docs/VERIFICATION.md` и VKH `docs/REGRESSION_CHECKLIST.md`.

## Важные границы

E-chat пока не содержит нативного APK/iOS-приложения, голосовых/видеозвонков, фонового Web Push, сквозного шифрования, публичного каталога каналов и автоматической очистки файлов/событий. В закрытом браузере новая доставка системных уведомлений не реализована. Без IP-связи сообщения только остаются в локальной очереди.

Ключ восстановления не отправляется серверу, но тексты сервер может расшифровывать своим ключом. Это не анонимность и не E2EE. Пользовательский ключ не восстанавливает уничтоженную серверную БД. Регистрация только по ID/ключу требует отдельной правовой оценки перед публичным запуском в РФ; источники и границы — `E-chat/docs/SECURITY.md`.

Сначала тестовая установка и исправление обнаруженного, затем ограниченный пилот. Не используйте эту версию как единственную копию критически важной переписки.
