# Проверки и приёмка — 25.09.2026

## Реально выполнено при подготовке

- **17 автоматических тестов прошли** на Python 3.13, SQLite и FastAPI TestClient. Отчёт: `verification/echat-pytest.log`.
- Реальная совместимость подписи Node.js WebCrypto P-256/P1363 с Python-проверкой подписи; кириллица и emoji в подписываемом контексте; отклонение подменённого payload/origin.
- Регистрация/восстановление, отзыв устройств, неправильная подпись и повтор challenge.
- Идемпотентный прямой диалог и повтор send, чужой доступ, монотонное прочтение, ответ в чужой диалог.
- Роли канала, приглашение, удаление/понижение участника, блокировка, передача владельца, повтор создания после передачи.
- Курсорные страницы без потерь на тестовом наборе, параллельная отправка и повтор одного ID **в SQLite**.
- Загрузка файла с продолжением, потерянное подтверждение блока, проверка SHA, ACL, Range 206, запрет выдачи удалённого вложения.
- Ограничения тела/Origin, шифрование сохранённого текста, пробуждение ожидающего sync после транзакции.
- Статическая проверка JavaScript, Python, shell и структуры конфигураций описана в `verification/static-checks.txt`.

Скриншотов успешной работы с устройств не заявляется.

## Как повторить серверные тесты

Из корня E-chat, в виртуальном окружении:

```sh
python -m pip install -r requirements-test.txt
PYTHONPATH=. python -m pytest -q tests
node --check web/app.js
node --check web/sw.js
```

Два теста WebCrypto требуют Node.js 22+; без Node они будут `skipped`, а не `passed`. В Windows PowerShell перед pytest используйте `$env:PYTHONPATH="."`, затем `python -m pytest -q tests`. Тесты создают временные SQLite-БД и не подключаются к рабочему серверу.

## Как выполнить браузерный сценарий

Первый терминал:

```sh
python scripts/dev.py
```

Второй терминал, тот же Python venv:

```sh
python -m pip install -r requirements-test.txt
python -m playwright install chromium
python tests/browser_smoke.py
```

По умолчанию сценарий использует `http://127.0.0.1:18080` и `browser-test-invite`. Результаты записываются в `reports/browser`; `CHROMIUM` позволяет указать локальный исполняемый файл браузера. Для смены тестового URL/приглашения предусмотрены `ECHAT_SMOKE_URL` и `ECHAT_SMOKE_INVITE`. **Не направляйте этот тест на production:** он создаёт аккаунты, сообщения и файлы.

Сценарий предназначен для двух аккаунтов, офлайн-перезагрузки и повторной отправки, потери HTTP-ACK, ограничения скорости через CDP, вложения и восстановления на третьем устройстве/мобильной ширине. Параметры CDP — модель сети, не реальная EDGE; даже успешный сценарий не даёт гарантии работы у любого оператора.

## Обязательная ручная приёмка

Проверьте на отдельном PostgreSQL-развёртывании минимум три аккаунта. Третий не должен читать/менять чужой диалог или скачивать его вложение даже при знании ID. Участник канала не публикует, удалённый участник теряет доступ; бывший администратор не продолжает загрузку после понижения.

Отключите сеть до send, во время блока файла, после коммита на сервере до ответа, затем перезапустите вкладку и восстановите сеть. В каждом случае проверьте единственную серверную запись, прежний `clientId`, правильный порядок и отсутствие потери текста. Прокрутите более 1000 сообщений назад и вернитесь к последним; чтение истории не должно превращаться в склейку несмежных фрагментов.

Проверьте 16/32/64 кбит/с, RTT 0.8–2 секунды, короткие окна связи и потери пакетов отдельно. Измеряйте суммарный сетевой трафик, а не только размер JSON. Для приёмки задайте свои численные критерии до теста; в пакете нет выдуманных p95/FPS.

Проверьте переполнение диска/квоты, отказ БД, перезагрузку сервера, согласованное восстановление бэкапа, появление пустого/отсутствующего общего mount на втором узле. Нельзя считать успешное выполнение миграции подтверждением этих сценариев.

Перед публичным запуском закройте известные продуктовые пробелы: системные push, процедуры абьюза/модерации, безопасное управление аккаунтами, хранение/очистку данных, независимый аудит и правовую квалификацию. До этого используйте пилот для ограниченных тестов, не для единственной копии критически важной переписки.

Дополнительно реально проверен запуск `scripts/dev.py`: отдельный локальный Uvicorn/SQLite-сервер, ответ 200 от `/health/ready` и семи ресурсов веб-клиента. См. `verification/http-smoke.json`. Это HTTP-проверка запуска и выдачи файлов, а не успешное испытание интерфейса в браузере.
