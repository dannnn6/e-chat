# E-chat — 0.1.0-pilot

Дата пакета: 25 сентября 2026 года. Самостоятельный сервер и устанавливаемый веб-клиент (PWA). Никаких рабочих учётных записей, таблиц, файлов конфигурации или ключей VKH в этом продукте нет.

## Статус — прочитать до установки

Это **исходный код функционального пилота**, а не подтверждённый production-релиз и не готовый эквивалент Telegram. Включены реальные сервер, интерфейс, миграция, контейнеры, очередь, восстановление и тесты. При подготовке прошли серверные тесты на SQLite и проверка совместимости WebCrypto. **PostgreSQL, Docker-развёртывание, полный браузерный сценарий и реальные EDGE/Android/iOS-устройства здесь не проверены.** Полный статус находится в `docs/VERIFICATION.md`.

Нативного Android APK, iOS-приложения, Windows EXE, звонков, сквозного шифрования, фонового Web Push и публичного каталога каналов в этом пакете нет. Каналы реализованы как диалоги с ограниченными правами публикации и входом по ID/приглашению. Интерфейс работает в браузере, а поддерживающий PWA браузер позволяет установить его отдельным значком.

**Для публичного запуска в РФ отдельно проверьте правовую применимость регистрации без телефона.** Техническая возможность не является заключением о соответствии законодательству. Подробнее — `docs/SECURITY.md`.

## Что реализовано

| Область | Реализация |
|---|---|
| Идентичность | Пара ключей P-256 на клиенте; публичный ID `e_…`; код восстановления `ECHAT1.…`; без телефона и почты |
| Вход | Подпись одноразового запроса, отдельный ключ устройства, список и отзыв устройств |
| Диалоги | Личные, группы, каналы, собственные заметки |
| Права | Владелец / администратор / участник; добавление и удаление участников, передача владения |
| Сообщения | Текст, ответ, редактирование, удаление для всех, поиск, отметки прочтения личных сообщений |
| Сеть | Постоянная локальная очередь, повтор с прежним `clientId`, курсорная синхронизация, асинхронное ожидание изменений |
| E-режим | Меньшие страницы, блоки загрузки по 32 КиБ, текст обгоняет файлы между подтверждёнными блоками, нет автоматической загрузки вложений |
| Вложения | До 4 файлов по 10 МиБ; загрузка с продолжением, SHA-256, проверка членства при скачивании |
| Сервер | Изолированная PostgreSQL в Docker Compose; SQLite для локального теста; `/health/live`, `/health/ready` |
| Несколько серверов | Дополнительные API-узлы с общей PostgreSQL, общим ключом и одним согласованным файловым хранилищем |

Удаление сообщения скрывает его и запрещает новое скачивание привязанного файла, но **не является гарантированным физическим стиранием из диска, резервных копий или устройств получателей**. Квота файлов в пилоте учитывает и незавершённые загрузки; автоматический сборщик мусора не включён.

## Самый быстрый локальный запуск

Нужен Python 3.13. Команды выполняются из распакованной папки `E-chat`.

Linux/macOS:

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python scripts/dev.py
```

Windows PowerShell:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe scripts\dev.py
```

Откройте `http://127.0.0.1:18080`. Локальный код приглашения: `browser-test-invite`. Это **только локальный тест**: сервер привязан к loopback, тестовый код нельзя использовать в публичном развёртывании. Не меняйте адрес на LAN-IP без настройки HTTPS. Ключ сервера и тестовая история сохраняются в `data/dev` и переживают перезапуск.

Для двух пользователей откройте разные профили браузера или обычное и приватное окно. Приватный режим не подходит для постоянного хранения очереди: его данные могут исчезнуть при закрытии.

## Запуск на сервере

Нужны отдельное DNS-имя, Docker Engine с Compose plugin и Python 3 для генератора конфигурации. Порты существующего VKH не трогаются.

```sh
cd E-chat
python3 scripts/init.py echat.YOUR-DOMAIN.example
bash scripts/up.sh
curl --fail http://127.0.0.1:3080/health/ready
```

Вместо примера укажите **свой реальный поддомен**. Скрипт создаёт `.env` один раз с независимыми случайными секретами. Повторный запуск генератора не перезапишет ключи.

Далее подключите отдельный HTTPS virtual host в 1Panel/OpenResty/Nginx Proxy Manager к API. Если 80/443 уже заняты, не запускайте дополнительный Caddy на этих портах. Все варианты с точными действиями: **`docs/DEPLOY.md`**.

## Первое использование

1. Откройте свой E-chat по HTTPS. Выберите создание аккаунта, введите имя и приглашение от владельца сервера.
2. Сохраните предложенный ключ восстановления **до подтверждения регистрации**. Он даёт контроль над аккаунтом. Не пересылайте его в переписке и не отдавайте администратору сервера.
3. Создайте аккаунт. В настройках скопируйте только публичный `e_…` ID; его можно сообщить собеседнику.
4. Во втором профиле/на втором устройстве создайте второго пользователя. Первый пользователь нажимает «Новый личный чат» и вводит его ID.
5. Для группы или канала используйте меню создания, затем добавление участников по ID либо код приглашения. Администраторы канала могут публиковать, обычные участники — читать.
6. Для перехода на новое устройство откройте **тот же сервер**, вкладку восстановления и вставьте сохранённый ключ. При необходимости отзовите остальные устройства.

Код восстановления возвращает доступ к учётной записи, а не заменяет резервную копию серверной истории. Если уничтожены серверная БД/файлы/ключ шифрования данных, одним пользовательским ключом историю восстановить нельзя.

## Что означает «работает при E»

Цель реализации — сохранять действия локально и экономно догружать их при появлении доступной связи. Это не обещание передачи при нулевой пропускной способности, отсутствии IP-маршрута, недоступном DNS/TLS или блокировке сервера. На слабой сети сначала проверьте текст, затем файлы.

Клиент сохраняет очередь перед очисткой поля ввода. Сервер подтверждает сообщение после транзакции. Потеря HTTP-ответа приводит к повтору с тем же ID, а не к новой записи. Большой файл уступает новому тексту **между блоками**, но уже отправленный сетевой блок мгновенно прервать без потери его передачи нельзя.

Закрытый браузер может приостановить работу PWA. Автоматическая отправка продолжится при следующем запуске. **Новых системных уведомлений при закрытом E-chat в этом пилоте нет.**
